# 0001: Clone-GitRepo 目录布局与 URL 解析约定

为 `Clone-GitRepo` 定义 GitHub 仓库的本地落盘布局：克隆目标为 `$GITHUB_HOME\<owner>\<repo>`（默认 `$HOME\github`），owner 与 repo 目录名统一小写；URL 解析采用宽容策略——接受 https、ssh 与 `owner/repo` 简写，忽略多余路径段与查询串，非 GitHub 主机报错。目录已存在且非空时跳过克隆。

这些约定在 2026-08-16 的 grill-with-docs 会话中与用户逐项确认（见 `CONTEXT.md` 词汇表），写进 ADR 是为了防止未来被"顺手修正"：

- **目录名小写**：GitHub URL 大小写不敏感，但目录名是文件系统事实。曾考虑保留 URL 原样大小写（更贴近 GitHub 显示名），最终选统一小写，换取目录布局的确定性——同一仓库不会因 URL 写法不同而出现两个目录。注意克隆地址本身保留原大小写，仅目录名小写。
- **宽容解析**：只取 `github.com` 后前两段，`/tree/main`、查询串、尾斜杠一律忽略；简写 `owner/repo` 隐含 github.com。曾考虑严格校验（多段即报错），最终选宽容以覆盖"从浏览器地址栏复制链接"的常见场景。代价是拼错链接可能静默克隆到错误仓库，由输出路径提示兜底。
- **跳过语义**：目标非空即跳过（幂等，可重复执行）；空目录则克隆进入，修复中断克隆留下的半成品。
- **非 GitHub 报错**：不退化、不通用化，命令只服务 GitHub；未来支持其他平台时再扩展。
